## Architect part (done)

- Services + actions (tested): `moveTask({ taskId, toListId, beforeId?, afterId? })` (top-level only, same project,
  subtree moves, a link to the target is dropped), `addTaskToList({ taskId, listId })` (any depth, same project, not
  home, not already linked), `removeTaskFromList({ taskId, listId })` (link only; never the home list).
- Data: every `TaskRowDTO` now has `linkedListIds`; `ListViewDTO.project.lists` and `TaskDetailDTO.project.lists` are
  the project's active lists in order (the pickers' source — never other projects).
- `src/hooks/use-task.ts`:
  - `useMoveTask()` → `mutateAsync({ taskId, fromListId: task.homeListId, toListId })` (the row leaves the old home
    list at once; sidebar counts refresh);
  - `useAddToList()` → `mutateAsync({ taskId, listId })`;
  - `useRemoveFromList()` → `mutateAsync({ taskId, listId })` (the linked row leaves that list at once).

  Failures toast inside the hooks: wrap in `try/catch` and only toast success yourself.
- `src/hooks/use-sidebar-drop.ts`: dropping a row on a sidebar list.
  - `useSidebarDrop()` → `{ begin(isValid), end() }` for the list view.
  - `useSidebarDropTarget()` → `{ listId, mode: "move" | "add" } | null` for the sidebar.

  A list counts as a target when its element (or an ancestor) has `data-drop-list-id`. Alt held = `"add"`.

### 1. Row menu (task-row-menu.tsx; handlers owned by list-view.tsx)

After the re-parenting items, add:
- **Move to** (submenu, `IconArrowRight`): the project's lists (`data.project.lists`) except the task's home list,
  each with `IconList`. **Hidden for subtasks** (`task.parentId !== null`) and when there's no other list.
  Picks call `moveTask.mutateAsync({ taskId, fromListId: task.homeListId, toListId })`.
- **Add to list** (submenu, `IconPlaylistAdd`): the project's lists except the home list and `task.linkedListIds`.
  Hidden when nothing is left. Picks call `addToList.mutateAsync({ taskId, listId })`.
- **Remove from this list** (`IconPlaylistX`): only on linked rows (`task.isLinkedHere`), for the list being viewed:
  `removeFromList.mutateAsync({ taskId, listId: <current list id> })`.

The linked marker (link icon on `isLinkedHere` rows) exists since T-09; keep it.

### 2. Drop a row on a sidebar list (list-view.tsx + project-tree.tsx)

- **project-tree.tsx:** give each list row element `data-drop-list-id={list.id}`. Read `useSidebarDropTarget()`.
  When it targets this list, highlight the row (`bg-selected text-selected-foreground ring-1 ring-primary/40`) and
  show a small right-aligned label instead of the count: "Move here" or "Add here" (11px, medium). Nothing else in
  the sidebar changes (sizes and positions stay as measured in T-09).
- **list-view.tsx:** `const sidebarDrop = useSidebarDrop()`.
  - In the list `DndContext`, add `onDragStart={({ active }) => sidebarDrop.begin(isValidFor(task))}` where `task`
    is the dragged row's task and `isValidFor(task) = (listId, mode) => listId !== <current list id> &&
    data.project.lists.some((l) => l.id === listId) && listId !== task.homeListId && (mode === "add" ?
    !task.linkedListIds.includes(listId) : task.parentId === null)`.
  - At the **top** of `onDragEnd`: `const drop = sidebarDrop.end();`. If `drop` is set, run move (`mode === "move"`)
    or add (`"add"`) and **return** without reordering.
  - Add `onDragCancel={() => sidebarDrop.end()}`.
  - Only rows that are already draggable (roots, Manual sort) take part; nothing changes for the others.

### 3. Task dialog

- **⋯ menu** (task-dialog.tsx), between Copy link and Convert to task: the same **Move to** submenu (top-level tasks
  only; `fromListId: task.homeList.id`) and **Add to list** submenu (lists except home and `task.linkedListIds`). The
  dialog stays open on the same task; its breadcrumb and Lists section update when it refetches.
- **Lists section** (properties-column.tsx), as in the design:
  - The section title row gets a `+` button on the right (16px `IconPlus`, muted, `aria-label="Add to list"`) that
    opens a dropdown of the addable lists (same filter as above). It's hidden when none are left.
  - Linked chips (outlined) get a small `×` (`aria-label="Remove from <list>"`) that calls `removeFromList`.
  - The home chip (filled) has no ×.
