### Decisions later tickets must respect

1. **Position collation.** Keys are base-62 and compare by code unit (`"Z" < "a"`). All 7
   `position` columns are `TEXT COLLATE "C"` (hand-added in the migration; Prisma doesn't
   model collation, so it causes no drift). In JS, sort with `comparePositions`, never
   `localeCompare`. **Any future migration that recreates a position column must keep
   `COLLATE "C"`.**
2. **Delete behaviour (verified on Neon).** `Task.homeListId` and `Task.statusId` are
   `ON DELETE RESTRICT`. Deleting a Project or Space still cascades fine, but deleting
   a List or Status that still has tasks fails. That matches 6.1.4 and 6.3.2: `deleteList`
   and `deleteStatus` must move tasks first. `Comment.authorId` and `Activity.actorId` are
   also RESTRICT, so a User with comments or activity can't be hard-deleted.
3. **Activity payloads used by the seed** (T-08 should match): `TASK_CREATED {}`,
   `SUBTASK_ADDED { subtaskId }` on the parent, `ASSIGNEE_ADDED { userId }`,
   `TASK_COMPLETED {}`, `ADDED_TO_LIST { listId }`, `COMMENT_ADDED { commentId }`.
4. **Date-only fields** are stored as UTC midnight with `dueHasTime = false`.
