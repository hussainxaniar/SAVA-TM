# T-19 · Google pull and reconciliation

**Model:** A (Sonnet 5.5 session, no implementer dispatch) · **Depends on:** T-18 · **Section:** 10.4

## What was built

- `googleApi.listEvents` (pages, `singleEvents`, `showDeleted`) and `getEvent` (404/410 = null).
- `listGoogleEvents(ctx, { rangeStart, rangeEnd })` in `google-calendar.ts` returns `{ events, changed }` (a small deviation
  from the blueprint's `GoogleEventDTO[]`, so the client knows to refetch my blocks):
  1. Events with our `appTimeBlockId`: moved → the block is updated and SCHEDULED is logged; cancelled → the block is
     deleted and UNSCHEDULED is logged. They are never returned as gray events.
  2. My synced blocks in range whose event didn't come back are looked up with `events.get`: gone or cancelled → the
     block is deleted; moved elsewhere → updated.
  3. Everything else comes back as a read-only `GoogleEventDTO` (timed or all-day).
- Not connected: nothing. Google unreachable: nothing (the calendar still works). A dead refresh token: the "Reconnect"
  message.
- UI: `useGoogleEvents` (enabled only while connected, 30 s stale, refetches on focus) feeds gray read-only blocks into
  the calendar grid; clicking one opens its Google link in a new tab. When reconciling changed a block, blocks, the rail and
  open dialogs are refetched.

## Checks

- 5 new tests (222 total, Google faked): other events (timed and all-day, cancelled skipped); a moved event updates the block and
  logs SCHEDULED, and is idempotent; a cancelled event deletes the block and logs UNSCHEDULED; missing events are looked
  up (deleted → block removed, moved away → block updated); Google unreachable returns nothing and a dead grant asks to reconnect.
- Browser: the calendar still renders without errors for a non-connected user. Seeing real events needs a real Google account.
