## Architect part (done)

- Service `setParent(ctx, { taskId, parentId | null })` (6.4.3) and `setParentAction`: same project only, no
  cycles, the whole subtree stays within three levels, the subtree takes the parent's home list; `null` promotes
  to a top-level task. Logs `PARENT_CHANGED`. Tested.
- `src/lib/list-view.ts`: `parentCandidates(tasks, taskId)` → the tasks of a list view that `taskId` may become a
  subtask of (same rules as the server, minus the project check, which a list always satisfies); `MAX_TASK_DEPTH`.
- `src/hooks/use-task.ts`:
  - `useAddSubtask()` → `mutate({ parentId, listId: parent.homeList.id, title, tempId: \`temp-${crypto.randomUUID()}\` })`
    (optimistic row in the dialog; the server's depth message rolls it back with a toast);
  - `useReorderSubtask()` → `mutate({ parentId, taskId, listId: parent.homeList.id, beforeId, afterId })`
    (beforeId = the subtask now directly **above** the moved one, afterId = directly **below**; null at the ends);
  - `useSetParent()` → `mutateAsync({ taskId, parentId })` (not optimistic; failures toast inside the hook, so
    wrap in `try/catch` and only toast success yourself);
  - `useEditTask()` now also updates the row in the parent's dialog, so a subtask's status change from the
    parent's dialog shows at once.

### 1. Dialog: Subtasks section (task-dialog.tsx)

Match the design's Subtasks block (margins, 14px semibold heading, `done/total`, 120×4 progress bar, 40px rows
with `border-divider` between them):

- **Always shown** now (T-11 hid it at 0). With no subtasks: "Subtasks" + muted `0`, no progress bar, then the
  add row (as in `task-dialog-empty`).
- **Rows:** a `StatusControl` (size 16, `statuses={task.statuses}`,
  `onSetStatus={(t, statusId, completeSubtasks) => editTask.mutate({ taskId: t.id, statusId, completeSubtasks })}`)
  instead of the plain glyph; the title (line-through + muted when done) is the click target that opens the
  subtask; due and avatars as now. Temporary rows (`temp-` ids) are not clickable and their status control is
  disabled.
- **Drag to reorder:** the whole row is draggable (dnd-kit sortable, vertical list). On drop compute the new
  neighbours and call `useReorderSubtask().mutate({ parentId: task.id, taskId, listId: task.homeList.id, beforeId,
  afterId })`. Clicks on the title and the status control must still work (the 4px activation handles it).
- **Add:** below the rows, a `+ Add subtask` button (`IconPlus` in `text-primary`, muted label, as in the design).
  Clicking it shows an input in its place: `Enter` creates via `useAddSubtask()` and keeps the input open and
  empty for the next one; `Esc`, or blur while empty, closes it (`stopPropagation` on Esc so the dialog stays
  open). Reuse `InlineAdd` if it fits; otherwise a plain input styled like the rows.
- **Depth limit:** when `task.depth >= MAX_TASK_DEPTH` (import from `@/lib/list-view`), don't render the add
  button; show muted 13px text "Subtasks can only go three levels deep." in its place.

### 2. Dialog: ⋯ menu

`task.parentId` is set: `await setParent.mutateAsync({ taskId: task.id, parentId: null })`, then
`toast.success("Converted to a task")`. The dialog stays open on the same task (its breadcrumb updates on refetch).

### 3. Row menu: Convert to task / Make subtask of…

In `task-row-menu.tsx` add two items between Priority and Delete (with a separator above them):
- **Make subtask of…** (icon: `SubtaskGlyph` from `status-icon.tsx`, the Paper design's subtask glyph — not Tabler's): opens the picker (4). Hide it
  when `parentCandidates` returns nothing.
- **Convert to task** (`IconCornerLeftUp`): only when `task.parentId` is set. Calls `setParent` with `parentId: null`, then

Wire the handlers through `list-view.tsx` (it owns `useSetParent()` and `data.tasks`) and `task-row.tsx`, the
same way `onDeleteTask` is passed today.

### 4. The "Make subtask of…" picker (`make-subtask-dialog.tsx`)

A small controlled dialog like quick add: `DialogContent showCloseButton={false}` at `top-[20%] translate-y-0`,
`sm:max-w-[480px] p-0 gap-0`; a visible title row "Make subtask of…" (13px semibold, muted, px-4 pt-3); a plain
borderless input (autofocus, placeholder "Search tasks") that filters by title (case-insensitive contains);
then up to 8 matches as `role="option"` rows (`h-9 px-3 text-sm`, highlighted `bg-accent`): `StatusGlyph` (14px)
+ title (truncate) + for depth-1 candidates a muted `↳ parent title` suffix. Keyboard: ↑/↓ move, Enter picks, Esc
closes. Click picks. No matches: muted "No matching task can hold it (three levels at most)."

Props: `{ open, onOpenChange, candidates: TaskRowDTO[], statuses: StatusDTO[], onPick: (parentId) => void }`.
In `list-view.tsx`: `candidates = parentCandidates(data.tasks, task.id)`; on pick close the picker, then
`await setParent.mutateAsync({ taskId, parentId })` and `toast.success(\`Moved under "${parent.title}"\`)`.
