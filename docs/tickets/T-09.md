- Theme tokens in `src/app/globals.css` (see the mapping table below); page
  `src/app/(app)/s/[spaceId]/p/[projectId]/l/[listId]/page.tsx` renders `<ListView>`.

### Design decisions (agreed with the human; they differ from blueprint 9.2 wording)

- Tasks are **grouped by status** (in status order) with collapsible pills; Done-category groups start
  collapsed. This is how "N completed" is hidden (6.7).
- The row "checkbox" is the **status icon** (dashed circle = To do, blue half-clock = Active, green check =
  Done). **Priority is a flag**, not the checkbox color.
- Row right side (NESTED): Subs (done/total), Assignee avatars, Due, Priority flag. No comment count, no status pill.

### Rules

- `"use client"`. Data: `const { data } = useListView(initialData.list.id, initialData)`; render from `data`.
  Groups: `useMemo(() => buildGroups(data.tasks, data.statuses, { mode: data.list.subtaskDisplay, sort, collapsed }), …)`.
- Mutations only through the hooks. Errors are already toasted by the hooks.
- **Base UI, not Radix:** `render={<Button …/>}` instead of `asChild`; `nativeButton={false}` when a Button
  renders a Link; `Select` needs `items`; `AlertDialogAction` doesn't close by itself; `DropdownMenuLabel` must
  be inside `DropdownMenuGroup`. Radio/checkbox items: `DropdownMenuRadioGroup` + `DropdownMenuRadioItem`,
  `DropdownMenuCheckboxItem` (see `src/components/ui/dropdown-menu.tsx`).
- **dnd-kit:** only `@dnd-kit/core` and `@dnd-kit/sortable`; `DndContext id={useId()}` (required; it prevents a
  hydration error); transform CSS written by hand, as in `project-tree.tsx`.
- **Colors: tokens, never hex** (dark mode must keep working):

| Design | Class |
|---|---|
| `#000` / `#18181B` text | `text-foreground` |
| `#3F3F46` | `text-foreground/80` |
| `#71717A`, `#52525B`, `#A1A1AA` | `text-muted-foreground` (use `/60` for `#A1A1AA`) |
| `#E8E8EA` group header border | `border-border` |
| `#F0F0F1` row divider | `border-divider` |
| `#F0F0F2` status pill | `bg-pill` |
| `#F6F6F7` hover row / header band | `bg-sidebar` (header band: `bg-sidebar/50`) |
| `#15803D` Done pill / check | `bg-done` / `text-done` |
| `#16A34A` "Today" | `text-success` |
| `#DC2626` overdue | `text-overdue` |
| `#3B82F6` active status icon | `text-status-active` |

| `#2563EB` add "+" | `text-primary` |
| avatars | inline `style` from `avatarColors(user.id)` |

- Inline the design's small SVGs (status icons, the subtask icon, the flag) as React components in
  `status-icon.tsx` / `priority-flag.tsx`, using `currentColor` and the classes above. Everything else is lucide.

### 3. Rows

Clicking the row background opens the task panel: `router.replace(\`${pathname}?task=${task.id}\`, { scroll: false })`
(T-11 builds the panel; for now the URL changes). Right-click also opens the row menu. Clicks on controls must
`stopPropagation`.

**Status icon** (both modes; a `<button>` with `aria-label="Complete <title>"`, or "Reopen <title>" when done):

| Category | Icon | Size |
|---|---|---|
| TODO | dashed circle (`strokeDasharray="3.2 3.2"`), muted | 18px |
| ACTIVE | circle plus a quarter wedge (see design), `text-status-active` | 18px |
| DONE | filled `text-done` circle with a white check | 16px |

Click: if done → `useSetCompleted` with `completed:false`. If not done and `openSubtaskCount > 0` → an
AlertDialog titled "Also complete N open subtask(s)?", with "Only this task" (outline) and "Complete all"
(primary, autofocus, calls `includeSubtasks:true`). Otherwise complete directly.

**NESTED row** (`h-9` minimum, `flex items-center border-b border-divider`, see `list-view-nested.jsx.txt`):
- cells in order: a 20px handle spacer, then **one 20px indent cell per `row.indent`**, then a 20px chevron cell
  (a `ChevronRight`/`ChevronDown` 12px toggle when `row.hasChildren`, which adds or removes the id in `collapsed`),
  then the status icon (`ml-0.5 mr-2.5`);
- the **title** 14px `text-foreground`, `font-medium` when `row.hasChildren`, truncate, grows. Done:
  `line-through text-muted-foreground`. When `task.isLinkedHere`, a 13px `Link` icon (`text-muted-foreground/60`,
  `title="Linked from another list"`) follows the title (gap 6px). When `row.showParent`, put a line above the
  title (the row grows): an 11px muted `↳ {task.parentTitle}` button that opens the parent (`?task=parentId`);
- **Subs** `w-14`: when `subtaskCount > 0`, the subtask icon 13px plus
  `${subtaskCount - openSubtaskCount}/${subtaskCount}`, 12px muted;
- **Assignee** `w-[72px]`: up to 3 avatars 22px `rounded-full`, 10px semibold initials, overlapping `-ml-1.5`
  with a `ring-2 ring-background` when more than one;
- **Due** `w-24`: `formatDue(...)` 13px. Tones: overdue `text-overdue`, today `text-success font-medium`,
  default `text-foreground/80`; completed rows are muted;
- **Pri** `w-8` centered: the flag 14px for P1–P3.
- **Hover** (design row "Hero section"): `rounded-md bg-sidebar -mx-2 px-2`; the drag handle (6-dot, 14px,
  `text-muted-foreground/60`) appears in the left gutter **outside** the column (absolute, `-left-[22px]`), and two
  26px buttons (`rounded-md border bg-background`), `+` (add subtask) and `⋯` (row menu), appear just before the
  Subs column (`mr-3`, gap 2px). Buttons stay visible while their menu is open.

**SEPARATE row** (see `list-view-separate.jsx.txt`): `flex items-start py-2.5 border-b border-divider`:
- the status icon 16px, aligned to the title line;
- a text column (gap 3px): when `row.showParent`, a parent line (subtask icon 12px plus the parent title, 12px
  muted, a button that opens the parent); the title 14px/20px (link icon and done styling as above); a meta line
  (`gap-3`, 12px muted): Due (`Calendar` 12px icon plus the label, with the tone color), Subs (icon plus
  done/total, only when > 0), and the flag 14px for P1–P3. Omit empty parts;
- assignees in a `w-16` centered column at the right. The hover state and actions are the same as NESTED.

### 4. Menus

- **View menu** (`DropdownMenu`, `align="end"`):
  - group "Subtasks": a radio group Nested / Separate → `useSetSubtaskDisplay` (a shared setting: say so in a muted
    label "Everyone sees this");
  - group "Sort": a radio group Manual / Due date / Priority → the sort preference;
  - `DropdownMenuCheckboxItem` "Show completed".
- **Header `⋯` menu**: "Rename list" (starts the inline title edit), "Project settings" →
  `router.push(\`/s/${spaceId}/p/${project.id}/settings\`)`, and when `canDeleteLists`, "Delete list…"
  (destructive) → the same settings route (deleting with a target list lives there).
- **Row menu** (the hover `⋯`, or right-click on the row): Open (sets `?task=`), Complete / Reopen (same
  logic as the status icon), a **Priority** submenu (Urgent P1 / High P2 / Medium P3 / None P4, each with its
  flag and a check on the current one) → `useUpdateTask({ taskId, priority })`, a separator, and **Delete**
  (destructive) → `useDeleteTask({ taskId, title })` (no confirm: the hook shows Undo). Move, add to list and
  dates come in later tickets; don't add them.

### 5. Inline add (group "Add task" and the row `+`)

An `Input`-like field in the row slot (`h-9`, 14px, no border, placeholder "Task name", autofocus).
- Group add → `useCreateTask(listId).mutate({ tempId: \`temp-${crypto.randomUUID()}\`, listId, title, statusId })`.
- Row `+` → the field appears **directly under that task's subtree** at `indent + 1` →
  `mutate({ tempId, listId, title, parentId: task.id })`, and the parent is removed from `collapsed`. Hide the
  `+` when `task.depth >= 2` (three levels max, 6.4.1).
- Enter with text: create, clear, **keep the field open**. Esc or blur-when-empty: close. Trim; ignore empty.
- Temporary rows (`id` starting `temp-`) render normally but aren't draggable and ignore clicks.

### 6. Drag to reorder (Manual sort only)

Only when `sort === "manual"`. A row is draggable when it's a **root**: `!task.parentId` or its parent isn't in
`data.tasks`. One `DndContext` for the list; one `SortableContext` per group with that group's root ids. In
NESTED, the sortable node wraps the root row **and its subtree rows**, so they move together (as in
`project-tree.tsx`). On drop inside the same group, compute the new root order of that group; then
`useReorderTask(listId).mutate({ taskId, beforeId: prevRootInGroup ?? null, afterId: nextRootInGroup ?? null })`.
Ignore drops across groups. With any other sort, don't render handles.

### Performance

It should stay smooth with 200 tasks. Memoize `buildGroups`, wrap row components in `React.memo`, and keep
per-row state local (hover, menus).
