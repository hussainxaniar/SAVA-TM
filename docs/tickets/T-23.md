### What already exists

- `listApiTokens(ctx, { spaceId })` (server, returns `ApiTokenDTO[]`), `createApiTokenAction({ spaceId, name, scope: "READ" | "WRITE", expiresInDays: 30 | 90 | 365 | null })`
  returning `{ ok: true, data: { id, token, prefix } }` (the secret is only in this result) and `revokeApiTokenAction({ tokenId })`. Both actions call `refresh()`, so the
  page re-renders with the new list; there is no client cache to patch (same pattern as `invite-links.tsx`).
- `FeedItemDTO` comments have `via: string | null`; activity items carry `payload.via === "mcp"` for entries made through a token.

**Decisions taken while building (deviations from the plan above):**
- No `Ctx.via`: the `AsyncLocalStorage` alone carries the label (blueprint 15.3 updated). The UI uses the server-props + `refresh()` pattern, not TanStack hooks.
- `quick_add` without a list goes to the first list of the first project (the server has no "last used list").
- Every id a tool receives is checked against the token's space first (`inSpace`), because the services only check that the *user* is a member of the entity's space; a user in two spaces
  could otherwise reach the other space with a token bound to one. Foreign ids answer `NOT_FOUND`. A test covers all seven tools that take ids.
- The endpoint is stateless JSON (no sessions, no SSE), the Origin check compares against `APP_URL`, 120 requests/min/token in memory, bodies over 1 MB refused.

**Fixed in review of Flash's UI:** the create dialog was too narrow for the setup snippets (widened to `sm:max-w-lg`). Nothing else needed changing (no event-bubbling, hydration or lint problems).
