## Architect part (do first; all of `src/server/`, `prisma/`, tests)

1. **Schema + migration** (`prisma migrate dev --name api_tokens`): `ApiTokenScope`, `ApiToken` (Section 15.2), `Comment.via String?`,
   relations on `User` and `Space`. Update the seed only if needed. Vercel/Hetzner apply it on deploy, so tell the owner a migration is coming.
2. **`src/server/services/api-tokens.ts`**: `createApiToken`, `listApiTokens`, `revokeApiToken`, `resolveApiToken` (15.3). Token = `sava_pat_` +
   `randomBytes(32).toString("base64url")`; store `sha256` hex and the 12-character prefix; max 10 live tokens per user and space;
   `requireMember` first; `resolveApiToken` re-checks membership and throttles `lastUsedAt` writes to once a minute.
3. **`Ctx.via`** (`src/server/services/types.ts`) and an `AsyncLocalStorage` (`src/server/mcp/context.ts`) that `logActivity`/`logActivities`
   read to add `via` to the payload. `addComment` stores `Comment.via` from the same context. No other service call site changes.
4. **`src/lib/plain-to-doc.ts`** (+ unit tests): plain text / simple Markdown paragraphs to Tiptap JSON, and `docToPlain` for output
   (reuse what exists in `src/lib` for `bodyText` if there is one).
5. **`src/server/mcp/server.ts`**: builds the MCP server for one request from `{ ctx, spaceId, scope }` and registers the tools of 15.4 with zod
   input schemas, each calling the existing services (`createTask`, `updateTask`, `setCompleted`, `setAssignees`, `addComment`, `getListView`,
   `getMyTasks`, `getTask`, `getSidebar`, ...). `quick_add` reuses `src/lib/quick-add-parser.ts` server-side. Tools outside the token's scope
   are not registered. Errors map as in 15.4.
6. **`src/app/api/mcp/route.ts`**: `POST` only; reads `Authorization: Bearer`; `resolveApiToken` (401 + `WWW-Authenticate: Bearer` on failure); Origin
   check; per-token rate limit (`src/server/mcp/rate-limit.ts`, 120/min, in memory); runs the SDK's Streamable HTTP transport in stateless
   mode inside the `AsyncLocalStorage` context. `GET`/`DELETE` return 405. Never log the Authorization header.
7. **Server actions** for the UI (`src/server/actions/api-tokens.ts` + `.schema.ts`): `createApiTokenAction`, `listApiTokensAction`, `revokeApiTokenAction`.
8. **Tests** (15.6): `tests/services/api-tokens.test.ts`, `tests/lib/plain-to-doc.test.ts`, `tests/mcp/*.test.ts` (call the route's `POST` with a real `Request`
   against the test database, fake nothing except the clock where needed).
9. Run `pnpm typecheck && pnpm lint && pnpm test`; commit; then write the handoff below if it needs changes, and dispatch the UI part.

### What to build

1. **`AiAccessCard`** under the Google card on the Integrations page: heading "AI access", one sentence explaining that tokens let an AI assistant
   read and create tasks as you in this space. A table of the user's tokens: name, scope badge (Read-only / Read and write), `prefix…`, last used
   (relative), expiry or "Never", a Revoke button with an `AlertDialog` confirm. Empty state: "No tokens yet".
2. **Create token dialog**: name (required, 60), scope (radio: Read-only / Read and write, default Read and write), expiry select (30 days / 90 days /
   1 year / Never; default 90 days). On success show the secret **once** in a read-only mono field with a Copy button, a warning "You won't see this again",
   and two tabs of snippets with the real `APP_URL` origin (`window.location.origin`) and the token filled in:
   Claude Code (`claude mcp add --transport http sava <origin>/api/mcp --header "Authorization: Bearer <token>"`) and
   Claude Desktop (JSON config with `npx mcp-remote`, see 15.5). Closing the dialog clears the secret from state.
3. Use TanStack Query hooks `useApiTokens(spaceId)` plus mutations with toast errors and invalidation (put the hooks in `src/hooks/use-api-tokens.ts`).
4. **"via AI" label**: where the activity feed renders an entry whose `payload.via === "mcp"`, and on a comment whose `via` is set, append a small muted
   "via AI" chip after the author's name. Only those two places.
5. Tabler icons only; theme tokens only; mobile layout: the table becomes stacked rows below 768px.
