## Architect part (done)

- **Service** `src/server/services/comments.ts` + actions `src/server/actions/comments.ts` (tested):
  - `getFeed`, `addComment`, `editComment` (author only) and `deleteComment` (the author or an Admin/Owner; soft).
  - `addComment` logs `COMMENT_ADDED`; that activity row is left out of the feed, since the comment itself is the
    entry.
- **`FeedItemDTO`** (types.ts):
  - **Comments:** `{ kind: "comment", author, body (Tiptap JSON | null), createdAt, editedAt, deleted, canEdit,
    canDelete }`.
  - **Activity:** `{ kind: "activity", actor, type, payload, labels, createdAt }`. It is structured on purpose:
    the browser builds the sentence, so dates and times read in the viewer's time zone.
- **`src/lib/activity-format.ts`** (tested for all 21 activity types):
  - `formatActivity(item)` → the sentence without the actor, e.g. "set priority to P1",
    "changed the status from To do to In progress".
  - `relativeTime(iso)` → "just now", "5m ago", "2h ago", "yesterday", "3d ago", "Sep 28".
- **`src/hooks/use-feed.ts`:**
  - `useFeed(taskId)` → `FeedItemDTO[]`, oldest first. It always fetches everything; the toggle filters on the client.
  - `useAddComment(taskId, me)` → `mutate({ body, tempId: \`temp-${crypto.randomUUID()}\` })`.
  - `useEditComment(taskId)` → `mutate({ commentId, body })`.
  - `useDeleteComment(taskId)` → `mutate({ commentId })`.

  All three mutations are optimistic. Task edits already refresh the feed, so new activity lines appear on their own.
- `TaskDialog` receives `me: UserLite` (the signed-in user) from the layout.

### 1. Placement (task-dialog.tsx)

The Activity section goes **below the Subtasks**, inside the main (left) scrolling column. It sits behind a divider
that spans the whole column (`border-t border-border`, cancel the column's padding with negative margins) and uses
the design's padding: 24px top/bottom, left aligned with the title text (64px from the column edge), 24px right.
`<ActivitySection taskId={task.id} me={me} />`.

### 2. Header

"Activity" (14px semibold) on the left. On the right, a segmented toggle **All | Comments**: `bg-pill rounded-md p-0.5`;
the active segment `bg-background rounded-[5px] text-foreground font-medium`, the other `text-muted-foreground`;
12px, `px-3 py-[3px]`. The default is All. The choice is local state, not persisted.

### 3. Entries (gap 12px, oldest first)

- **Activity** (All only): a 22px `Avatar` + one 13px/18px line in `text-foreground/75`:
  `{firstName(actor)} {formatActivity(item)} · {relativeTime(item.createdAt)}`. `firstName` = the first word of the
  name.
- **Comment:** a 22px `Avatar`, then a column with a 2px gap:
  - first line, 13px `text-foreground/75`: `{firstName} · {relativeTime}`, plus ` · edited` when `editedAt` is set;
  - then the body: 14px/20px `text-foreground`, rendered read-only with Tiptap (same extensions as the composer,
    `editable: false`, `immediatelyRender: false`, class `rich-text`);
  - a deleted comment shows the muted italic text "Comment deleted" instead of the body, and no menu.

  On hover, a comment with `canEdit` or `canDelete` shows a small `⋯` (`IconDots`, 24px ghost) at the right with
  **Edit** (if `canEdit`) and **Delete** (if `canDelete`):
  - **Edit** swaps the body for the comment editor (4), prefilled. Save (or Ctrl/Cmd+Enter) →
    `editComment.mutate`; Cancel (or Esc, with `stopPropagation` so the dialog stays open) restores it.
  - **Delete** opens a controlled `AlertDialog` "Delete this comment?" (Cancel / Delete, destructive) →
    `deleteComment.mutate`.

  Temporary comments (`temp-` ids) show no menu.
- **Comments** filter with no comments: muted 13px "No comments yet."

### 4. Composer (`comment-editor.tsx`)

At the bottom of the section (after the entries, 12px gap): `me`'s `Avatar` at 44px (`className="size-11 text-[11px]"`)
and a rounded field: `min-h-11 rounded-[22px] border border-border px-4 py-[11px]`, grows with its content. Inside
it is a Tiptap editor:
- extensions `StarterKit` (headings off: `heading: false`), `Link.configure({ openOnClick: false, autolink: true })`
  and `Placeholder.configure({ placeholder: "Comment" })`;
- class `rich-text text-sm`;
- `immediatelyRender: false`.

**Ctrl/Cmd+Enter** sends: when the editor has text, `addComment.mutate({ body: editor.getJSON(), tempId })`, then
clear it and keep focus. Enter alone makes a new line. While the editor has text, show a small "Send" `Button
size="sm"` inside the field on the right (`aria-label="Send comment"`). No paperclip: attachments are not in v1.

Make the editor reusable for inline edit: `CommentEditor({ initial?, placeholder, onSubmit(body), onCancel?,
submitLabel })`. Esc calls `onCancel` when given, with `stopPropagation`.
