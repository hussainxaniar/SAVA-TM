# T-20 · Docs and pages

**Model:** A + I (Architect part by Sonnet 5.5; UI by GLM 5.3 Flash in three small tickets) · **Depends on:** T-19 · **Sections:** 8.7, 11

## Architect part (done)

- `src/server/services/docs.ts` (+ actions, schemas, 7 tests): `createDoc` (with one empty page), `renameDoc`,
  `reorderDoc`, `archiveDoc`, `getPageTree`, `getPage`, `getDocView`, `createPage` (≤ 3 levels), `savePage`, `movePage`, `deletePage`.
  - `savePage` is one conditional update on `updatedAt`, so two saves from one version can't both win. A conflict returns
    `{ conflict: true, updatedBy, updatedAt }`, and Overwrite resends with that `updatedAt`.
  - `movePage` rejects cycles, other docs and subtrees that would pass three levels. `deletePage` cascades and never leaves a doc without a page.
  - The schema has no `updatedBy` relation on `DocPage`, so the last editor is looked up from `updatedById`; no migration was needed.
- `src/lib/page-tree.ts` (5 tests): `flattenTree`, `subtreeIds`, `subtreeHeight` and `projectDrop`, the drag maths for
  re-nesting by horizontal drag.
- `src/hooks/use-doc.ts` (tree and page queries, create / move / delete) and `src/hooks/use-page-autosave.ts` (debounce, one save
  in flight, conflict pause, Reload / Overwrite, flush on blur / unmount / hide / close).
- The route `.../d/[docId]/[pageId]` fetches `getDocView`; `DocView` is the stub the UI fills.
