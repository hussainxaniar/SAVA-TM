## Architect part (done)

- `getTask` (`TaskDetailDTO`) now also returns `project: { id, name, color }` and `statuses` (the project's
  statuses in position order) — everything the dialog needs comes from one query.
- `src/hooks/use-task.ts`:
  - `useTask(taskId | null)` → the `['task', id]` query (not retried on NOT_FOUND; check
    `error instanceof ActionError && error.code === "NOT_FOUND"`).
  - `useEditTask()` → `mutate({ taskId, title?, description?, statusId?, completeSubtasks? })`. Optimistic in
    the dialog **and** in every cached list view showing the task; rolls back with an error toast.
  - `useDeleteTaskAnywhere()` → `mutate({ taskId, title })`: removes it from every cached list, then shows the
    10-second Undo toast. You close the dialog.
- `src/lib/task-nav.ts`: `publishTaskOrder(ids)` (views publish the ids of the rows on screen, in order) and
  `useTaskOrder()` (the dialog reads them for ↑/↓).
- `src/app/(app)/s/[spaceId]/layout.tsx` mounts `<TaskDialogHost spaceId />` inside `<Suspense>`;
  `src/components/task-dialog/task-dialog-host.tsx` is a stub with the props type: implement it there.
- `globals.css`: `.rich-text` styles for the Tiptap editor (placeholder, lists, links, code) and the
  `bg-panel` token (the properties column's background, light and dark).

### 1. Host, URL and navigation (`task-dialog-host.tsx`)

- `const taskId = useSearchParams().get("task")`. The dialog is open while `taskId` is set, on every page of the
  space (reload keeps it open because the id is in the URL).
- **Close** (`Esc`, `×`, click outside): `router.replace(<same path and query without "task">, { scroll: false })`.
- **Open another task** (breadcrumb ancestor, subtask row, ↑/↓): `router.replace(<same path with task=<id>>, { scroll: false })`.
  Write one small helper that builds these URLs from `usePathname()` and the current search params.
- **↑ / ↓**: `useTaskOrder()` gives the ids on screen. Previous/next = the neighbours of `taskId` in it. The header
  buttons are disabled at the ends and when `taskId` isn't in the order (e.g. opened from a link on another page).
  The **ArrowUp / ArrowDown** keys do the same when no modifier is held and focus is not in an `input`, `textarea`
  or `[contenteditable]` (listen on the dialog popup's `onKeyDown`).
- Dialog: shadcn `Dialog` (controlled: `open={!!taskId}`, `onOpenChange={(o) => !o && close()}`) with
  `DialogContent showCloseButton={false}` and classes for the design's box: 1080×780, radius 12, shadow
  `shadow-[0_24px_64px_rgb(24_24_27/0.28)]`, `p-0 gap-0`, `flex flex-col overflow-hidden`,
  `sm:max-w-[1080px] max-w-[calc(100vw-2rem)] max-h-[calc(100dvh-2rem)]`; below 768px full screen
  (`max-md:h-dvh max-md:w-screen max-md:max-w-none max-md:rounded-none`). Visually hidden `DialogTitle` = the
  task title.
- **Loading** (no data yet): the same box with the header's close button and a few muted skeleton bars (no
  spinner). **Not found / error**: centered muted text "This task was deleted or you don't have access." and a
  "Close" button.

### 2. Header (56px, bottom border `border-divider`, as in the design)

- **Breadcrumb** (left, 13px, muted, `/` separators): 8px rounded-[2px] square in `project.color` +
  project name (a `Link` to `/s/{spaceId}/p/{projectId}`), then the home list name (a `Link` to
  `/s/{spaceId}/p/{projectId}/l/{homeList.id}`), then each ancestor in `breadcrumb` (a button that opens that
  task). Truncate long parts. Following a breadcrumb `Link` closes the dialog (the new URL has no `?task`).
- **Right:** `IconChevronUp`, `IconChevronDown` (previous / next), `IconDots` (menu), `IconX` (close); 28px ghost
  icon buttons with `aria-label`s "Previous task", "Next task", "Task actions", "Close".
- **⋯ menu** (T-11 items only): **Copy link** (`navigator.clipboard.writeText(<origin>/s/{spaceId}/p/{projectId}/l/{homeList.id}?task={id}`), toast "Link copied")
  and **Delete** (`useDeleteTaskAnywhere().mutate({ taskId, title })`, then close; no confirm, the toast has Undo).

### 3. Main column (left, scrolls; padding and gaps as in the design)

1. **Title row:** the status control (see 4, ~22px glyph) and the title: 24px/32px semibold, `tracking-[-0.015em]`.
   Inline-editable: an auto-growing `<textarea rows={1}>` styled like the heading (no border, no resize,
   `field-sizing-content` or a height reset on input). `Enter` commits (no newlines), `Esc` reverts and blurs
   (`stopPropagation` so the dialog stays open), blur commits. Commit = trimmed, non-empty, changed →
   `editTask.mutate({ taskId, title })`; empty reverts. `maxLength={500}`.
2. **Description row:** `IconAlignLeft` (16px, muted, aligned with the first line) + a Tiptap editor:
   `useEditor({ extensions: [StarterKit, Placeholder.configure({ placeholder: "Description" }), Link.configure({ openOnClick: false, autolink: true })], content: task.description ?? "", immediatelyRender: false, editorProps: { attributes: { class: "rich-text min-h-[22px]" } } })`.
   Put the editor in its own component **keyed by task id**, so it remounts for another task and never resets
   while typing. **Autosave:** on update, debounce 800ms, then `editTask.mutate({ taskId, description })` with
   `editor.isEmpty ? null : editor.getJSON()`. Flush the pending save immediately on blur and on unmount (closing
   or stepping to another task). Skip a save when the JSON equals the last saved one.
3. **Subtasks** (read-only in T-11; only when `subtaskCount > 0`): "Subtasks" (13px semibold) + muted
   `done/total` + a 120×4 rounded progress bar (`bg-pill` track, `bg-success` fill), then compact 40px rows
   separated by `border-divider`: `StatusGlyph` (16px), title (line-through + muted when done), due
   (`formatDue`, 12px, tone colors as in the list), assignee avatars (`Avatar`, 20px). Clicking a row opens that
   subtask. (`+ Add subtask` is T-12.)

### 4. Status control

Reuse `StatusControl` from `status-icon.tsx` with `onSetStatus={(t, statusId, completeSubtasks) =>
editTask.mutate({ taskId: t.id, statusId, completeSubtasks })}` and `statuses={task.statuses}`. You may add two
**optional** props to it without changing current behavior: `size?: number` (glyph size, default as now) and
`variant?: "icon" | "pill"` (default `"icon"`). `"pill"` renders the trigger as the design's status pill: `h-7
rounded-md bg-pill px-2 gap-1.5`, a 14px `StatusGlyph` + the status name uppercase 12px semibold
`tracking-[0.04em]` (DONE: `bg-done text-white`, glyph with `pill`).

### 5. Properties column (right, 320px, `bg-panel`, left border `border-divider`, px-6, scrolls)

Sections separated by `border-divider`, each with a 13px semibold title and the design's spacing. Values are
read-only in T-11:

- **Status:** `StatusControl variant="pill"`.
- **Assignees:** one row per assignee: `Avatar` (20px) + name (14px). None → muted "No one".
- **Dates:** rows "Start" and "Due" (muted 56px label column) with `IconCalendar` (16px, muted; the Due icon
  takes the due tone color) and the value: `formatDue(...).label` (the due value colored by tone). Empty →
  muted "None".
- **Priority:** `PriorityFlag` + "P1"–"P3"; P4 → muted "None".
- **Lists:** the home list as a filled chip (`bg-pill`, radius 6, 12px) and each linked list as an outlined chip
  (`border`), no `×` yet.
- **Scheduled:** one row per time block: `IconClock` + "Today 10:45–12:00" style text (day label from
  `formatDue(start, false).label`-style logic: Today / Tomorrow / "Oct 3", then local start–end times); empty →
  muted "Nothing scheduled".

### 6. List view publishes its order (`list-view.tsx`)

Compute the ids of the rows currently rendered, in screen order (groups in order, only open groups, rows as
rendered; skip `temp-` ids), memoized, and `publishTaskOrder(ids)` in an effect; publish `[]` on unmount.
