### Rules for all five components

- `"use client"`. Import actions from `@/server/actions/spaces` and schemas from
  `@/server/actions/spaces.schema`. Every action returns
  `{ ok: true, data } | { ok: false, error: { code, message } }`.
- **Don't refetch or patch lists yourself.** The settings actions call `refresh()`
  on the server, so the page re-renders with fresh props after success.
- **Errors:** forms show `error.message` inline
  (`<p role="alert" className="text-sm text-destructive">`). Row actions (role change,
  remove, revoke) use `toast.error(message)` from `sonner` (already mounted). Success is
  silent, apart from the "Copied" feedback described below.
- Disable the control that triggered an action while it's pending.
- Layout and look: each settings section is a `<section className="space-y-4">` with an
  `<h2 className="text-base font-semibold">` and an optional
  `<p className="text-sm text-muted-foreground">` intro. Rows are divs, not `<table>`
  (`divide-y rounded-lg border`, each row `flex items-center gap-3 px-4 py-3`).
  Spacing uses the 4px grid; radius 6px (`rounded-md`) on inputs and pills.
- Roles are shown as `Owner` / `Admin` / `Member`.

### Base UI gotchas (these components are Base UI, not Radix)

- No `asChild`. To make a trigger look like a Button, use `render`:
  `<AlertDialogTrigger render={<Button variant="ghost" size="sm" />}>Remove</AlertDialogTrigger>`.
- **Select:** pass `items` so the trigger shows the label, not the raw value:
  `<Select items={{ ADMIN: "Admin", MEMBER: "Member" }} value={role} onValueChange={(v) => …}>`
  with `<SelectTrigger><SelectValue /></SelectTrigger>` and
  `<SelectContent>{…<SelectItem value="ADMIN">Admin</SelectItem>}</SelectContent>`.
  `onValueChange` receives the value first, and it can be `null`, so guard against it.
  Numeric options work as string values: convert with `Number(v)`.
- **AlertDialog:** `AlertDialogAction` is a plain Button that does **not** close the
  dialog. Control it: `const [open, setOpen] = useState(false)`,
  `<AlertDialog open={open} onOpenChange={setOpen}>`, and in the action's `onClick`
  await the server action, then `setOpen(false)` on success. On error, `toast.error` and
  keep the dialog open. `AlertDialogCancel` closes on its own.

### 1. `SpaceNameForm({ spaceId, name, canRename })`

Section "Space name". When `canRename`: `Input` (defaultValue `name`, `maxLength={80}`) and
a "Save" `Button` beside it, disabled until the value differs from `name` (trimmed), and
while pending. It validates with `renameSpaceSchema` and calls
`renameSpaceAction({ spaceId, name })`, showing errors inline. When not `canRename`, show
the name as plain text plus the muted note "Only the Owner can rename the space."

### 2. `MembersTable({ spaceId, members })`

Section "Members", intro "Everyone here can see all projects, lists, tasks and docs."
`members: MemberRow[]` = `MemberDTO & { isViewer, canChangeRole, canRemove }`, already
ordered. Each row shows:
- `Avatar` (size 32px) with `AvatarImage src={image}` when set and `AvatarFallback` with
  initials (first letters of the first two words of `name`, uppercased);
- name (`text-sm font-medium`, plus a muted " (you)" when `isViewer`) and email under it
  (`text-xs text-muted-foreground`), both `truncate`, in a `min-w-0 flex-1` column;
- role: if `canChangeRole`, a `Select` with Owner/Admin/Member (`w-28`); on change it calls
  `changeRoleAction({ spaceId, userId, role })` and shows `toast.error` on failure. The
  server enforces the last-owner rule, so just surface its message. Otherwise, a
  `Badge variant="secondary"` with the role;
- if `canRemove`: a ghost "Remove" button that opens an AlertDialog —
  title "Remove <name>?", description "They lose access to this space and are unassigned
  from its tasks." — with Cancel and a destructive "Remove" action calling
  `removeMemberAction({ spaceId, userId })`.

### 3. `InviteLinks({ spaceId, invites })`

Rendered only for Admins/Owners. Section "Invite links", intro "Anyone with a link can
join this space until it expires or runs out of uses."

**Create form** (one row, wraps on small widths): Role `Select` (Admin / Member, default
Member) · Expires `Select` (1 day / 7 days / 30 days, default 7 days; values "1" "7" "30") ·
Max uses `Input type="number" min={1} max={1000}` with placeholder "Unlimited" (empty =
unlimited → `null`) · "Create link" `Button`. It validates with `createInviteSchema`, calls
`createInviteAction({ spaceId, role, expiresInDays, maxUses })`, and shows errors inline.
On success, copy `res.data.url` to the clipboard (see below) and reset max uses to empty.

**List**: one row per invite (already newest first). Empty state: muted
"No invite links yet." Each row shows:
- role `Badge`; the URL in `font-mono text-xs truncate` (min-w-0 flex-1);
- usage: `uses` + (`maxUses` ? ` / ${maxUses}` : "") + " uses";
- expiry: when `status === "ACTIVE"`, "Expires " + relative time via
  `formatDistanceToNow(new Date(expiresAt), { addSuffix: true })` from `date-fns`
  (already installed). Otherwise a `Badge variant="outline"` reading "Expired" or "Used up";
- "Copy" ghost button (only when ACTIVE): `navigator.clipboard.writeText(url)`. The label
  changes to "Copied" for 2 seconds. If the clipboard call throws, `toast.error("Couldn't copy the link")`;
- "Revoke" ghost button: `revokeInviteAction({ inviteId: id })`, no confirm dialog.

### 4. `LeaveSpace({ spaceId, spaceName })`

Section "Leave space", intro "You'll lose access until someone invites you again."
Outline destructive-looking button "Leave space" that opens an AlertDialog —
title "Leave <spaceName>?" — with Cancel and a destructive "Leave" action calling
`leaveSpaceAction({ spaceId })`. On success `router.push("/")` (from `next/navigation`),
then `router.refresh()`. On error (e.g. the only Owner), `toast.error(message)` and keep
the dialog open.

### 5. `InviteCard({ token, spaceName, role, problem, signedInAs })`

The only content of `/invite/[token]`, centered. A `w-full max-w-sm space-y-6` card
(`rounded-lg border p-6`).
- **`problem` set** (invalid link): heading "Invite unavailable", `problem` as the
  paragraph, and a link-styled button to `/` reading "Go to Sava TM".
- **Valid, signed out** (`signedInAs === null`): heading "Join <spaceName>", text
  "You've been invited to join as <Admin|Member>. Sign in or create an account to accept."
  Two full-width buttons as `next/link` links (use
  `<Button nativeButton={false} render={<Link href=… />}>…</Button>`, not `asChild`.
  `nativeButton={false}` is required whenever a Button renders something other than a
  `<button>`):
  "Create account" → `/sign-up?next=/invite/<token>` (default variant) and "Sign in" →
  `/sign-in?next=/invite/<token>` (outline). URL-encode the `next` value with
  `encodeURIComponent`.
- **Valid, signed in**: heading "Join <spaceName>", text "You'll join as <Admin|Member>.",
  muted "Signed in as <signedInAs>", and a full-width "Join <spaceName>" button calling
  `acceptInviteAction({ token })`. On success `router.push(\`/s/${res.data.spaceId}\`)`.
  On error, show the message inline.
