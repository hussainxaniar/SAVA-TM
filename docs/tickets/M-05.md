## Architect part (done, do not change)

- `CalendarGrid` (`src/components/calendar/calendar-grid.tsx`) has a phone mode: `<CalendarGrid mobile onBlockTap={…} … />` starts in the 3-day view
  (`THREE_DAY_VIEW`, exported), uses long-press dragging, draws the phone day header, has no hover menu on blocks, calls `onBlockTap(block: BlockTap)` when one of my blocks
  is tapped (type exported: `timeBlockId, taskId, title, start: Date, end: Date, color, completed, syncState, lastSyncError`), and after an external drop creates the block
  and shows a "Scheduled …" toast with Undo. The other props are as on desktop (`spaceId`, `range`, `calendarRef`, `onDatesSet`, `onOpenTask`).
- `useTaskDragSource<HTMLDivElement>({ onDragStart, onDragEnd })` (`@/hooks/use-task-drag-source`) returns a ref for the element that contains the draggable rows. A row is
  an element with `data-task-id`, `data-title`, `data-color` and the class `sava-drag-row`. A long press (350ms) lifts the row; **the panel that holds the rows must stay
  mounted during the drag and must move out of the way** (FullCalendar only drops where the grid is the topmost element), which is why it is not a `BottomSheet`.
- `swipeDirection(start, end)` (`@/lib/swipe`) → `"left" | "right" | null` for points `{ x, y, t }` (t in ms).
- CSS: the grid wrapper needs the classes `sava-calendar sava-calendar-phone`.
- Hooks (`@/hooks/use-calendar`): `useCalendarTasks(spaceId, null)` → `CalendarTaskDTO[]` (a `MyTaskDTO` plus `nextBlockStart`), `useDeleteTimeBlock(spaceId).mutate({ timeBlockId, taskId })`,
  `useRetrySync(spaceId).mutate({ timeBlockId, taskId })`, `useGoogleConnection().data?.connected`, type `Range`.
- `BottomSheet`, `BottomSheetOption` (`@/components/ui/bottom-sheet`), `HeaderIconButton` (`src/components/mobile/screen-header.tsx`), `formatDue` (`@/lib/list-view`).
- Read `src/components/calendar/calendar-view.tsx` for how the desktop view wires `calendarRef`, `onDatesSet`, `range` and `onOpenTask`.
